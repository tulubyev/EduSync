# Лента ученика: события обучения

Этап 1 плана (#17, `docs/PRODUCT-PLAN.md`). Все уроки, вебинары, задания, экзамены и дедлайны ученика — ручные и
с площадок — лежат в одной таблице `learning_events`. По ней строятся календарь, блок «Сегодня» на главной,
страница «Дедлайны» и контекст ИИ-помощника. Эта же модель станет основой формата обмена с площадками (#19).

## Модель

| Поле | Что это |
|---|---|
| `type` | `lesson`, `webinar`, `assignment`, `exam`, `deadline` |
| `starts_at` | начало в UTC; у задания, экзамена и дедлайна — срок сдачи |
| `duration_minutes`, `time_zone` | длительность и пояс, в котором событие задала площадка или ученик |
| `program_title`, `module_title`, `course_id` | программа → модуль → событие; `course_id` — ссылка на курс ученика, если он есть |
| `lesson_url`, `materials_url`, `join_url` | «Открыть урок», «Материалы», «Войти на вебинар» — только http(s) |
| `source`, `external_id`, `platform_id` | `manual` или код площадки (`stepik`, …); пара `source` + `external_id` уникальна у ученика |
| `status`, `priority`, `completed_at` | `pending` / `completed` / `cancelled`; «просрочено» не хранится, а считается по сроку |
| `recording_task_id` | запись вебинара в Help Recorder («Не смогу прийти → Записать») |

Таблица создаётся скриптом `scripts/sql/2026-10-25-learning-events.sql`. Он же переносит ручные дедлайны из
`deadlines` с теми же id. Старые таблицы `deadlines` и `course_deadlines` больше не используются и будут удалены
вместе с объединением `courses` и `external_courses`.

## API

Все маршруты требуют входа; чужие события отвечают 404.

| Маршрут | Что делает |
|---|---|
| `GET /api/events?from=&to=` | события периода (ISO, не больше 400 дней; по умолчанию неделя назад и два месяца вперёд), отменённые — с `cancelled=1` |
| `POST /api/events` | новое ручное событие |
| `PATCH /api/events/:id` | правка, `status`, связь с записью `recordingTaskId` (только своя запись) |
| `DELETE /api/events/:id` | ручное событие удаляется; событие площадки отменяется, иначе вернулось бы при синхронизации |

`/api/deadlines` работает как раньше, но читает и пишет `learning_events` (типы `deadline`, `assignment`, `exam`).

## Источники

Адаптер площадки отдаёт события в `eventStorage.upsertSourceEvents(userId, source, platformId, items)`:
новые добавляются, известные по `external_id` обновляются; статус, важность и запись остаются за учеником.
Синхронизация Stepik пишет сроки разделов через этот же вход.

## Клиент

- `/calendar` — «Неделя / Месяц», выбор пояса (общий с экранами записи), быстрый ввод.
- Главная — блок «Сегодня»: просроченное, события дня, ближайшие на неделю.
- Быстрый ввод одной строкой разбирает `shared/learningEvents.ts`: «Вебинар по Python завтра в 19:00 1ч https://…»,
  «Сдать эссе до пятницы !», «Lecture on Monday at 6:30pm 90 min».
