# Выгрузка данных ученика

Задача #44. Ученик скачивает все свои данные одним архивом: «Настройки» → «Профиль» → «Скачать мои данные».
Это право на доступ и переносимость данных — ст. 14 152-ФЗ, ст. 15 и 20 GDPR (контур EU, `docs/DATA-REGIONS.md`).

## Что в архиве

`README.txt` на языке ученика и файлы:

| Файл | Что внутри |
|---|---|
| `profile.json` | профиль |
| `settings.json` | настройки |
| `courses.json`, `courses.csv` | курсы и программы |
| `events.json`, `events.csv`, `calendar.ics` | уроки, вебинары, задания, экзамены, дедлайны |
| `library.json` | библиотека |
| `study-sessions.json` | учебные сессии |
| `recordings.json` | записи трансляций — сведения, сами видео скачиваются в «Записях» |
| `platforms.json` | подключённые площадки |
| `subscriptions.json`, `payments.json` | подписка и платежи |
| `profile-image.*` | фото профиля, если есть |

**Никогда не выгружаются:** хеш пароля, секрет ленты календаря, токены площадок, пароль трансляции, служебные поля
воркера, сохранённые способы оплаты (`SECRET_FIELDS` в `server/services/dataExportFiles.ts`, тест проверяет каждый файл).
CSV открывается в Excel без искажений (BOM); значения, начинающиеся с `=`, `+`, `-`, `@`, экранируются — формулы не выполняются.

## Как устроено

- `GET /api/profile/export` — только данные из `req.user.id`, не чаще раза в 10 минут (429 с `Retry-After`).
  Счётчик в памяти процесса: при нескольких процессах — раз в 10 минут на каждый.
- `server/services/dataExport.ts` — сбор из базы; `dataExportFiles.ts` — чистая сборка файлов (тесты);
  `zip.ts` — запись ZIP без зависимостей (deflate, имена в UTF-8; тест читает архив обратно, архив проверен `unzip -t`).
- Старые таблицы: `deadlines` и `external_courses` перенесены в события и курсы (#17) и отдельно не выгружаются;
  строки `course_deadlines` (сроки площадок до #17), если остались, попадают в `platform-deadlines-legacy.json`.
