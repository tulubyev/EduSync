# Региональные контуры хранения персональных данных

Этап 1 плана (#17). Решение владельца: контуры РФ, ЕС и «остальной мир», с возможностью добавить регион, если
этого требует местный закон. Архитектура закладывается сразу, а пока работает один сервер в РФ.

## Что такое контур

Контур — отдельная установка My EPA: свой сервер, своя база, свой домен. Весь код одинаковый, отличаются только
переменные окружения. Данные ученика лежат ровно в одном контуре:

- учётная запись, курсы, события ленты, заметки, записи вебинаров;
- подключения к площадкам и обмен данными с ними.

Общие для всех контуров только обезличенные справочники: площадки и каталог курсов. В них нет данных учеников.

| Контур | Страны | Закон |
|---|---|---|
| `ru` | Россия | 152-ФЗ, ч. 5 ст. 18 — данные граждан РФ хранятся в базах на территории РФ |
| `eu` | ЕС, ЕЭЗ (Исландия, Лихтенштейн, Норвегия), Великобритания, Швейцария | GDPR, UK GDPR, FADP |
| `world` | все остальные | — |

Список стран — `shared/dataRegions.ts` (`REGION_COUNTRIES`).

## Два поля у ученика

- `users.home_region` — где данные **должны** храниться по закону его страны. Определяется по стране при регистрации.
- `users.data_region` — где они хранятся **на самом деле**.

Пока контура для `home_region` нет, ученик хранится в основном контуре (`ru`) по согласию на трансграничную
передачу. Оно есть в тексте согласия при регистрации (`docs/legal`). Такие учётные записи видны по условию
`home_region <> data_region`.

## Регистрация

`placeRegistration(country, deployment)` в `shared/dataRegions.ts`:

| Ситуация | Что происходит |
|---|---|
| Регион ученика — это текущий контур | учётная запись создаётся здесь |
| Контур региона ученика открыт в другом месте | ответ `409 { code: "region_redirect", url }`, форма предлагает перейти на сайт его контура |
| Контура региона ученика ещё нет | учётная запись создаётся здесь, `home_region` ≠ `data_region` |

## Настройка установки

```
DATA_REGION=ru                                            # какой это контур (по умолчанию ru)
DATA_REGION_URLS=eu=https://eu.example.com,world=https://world.example.com   # другие открытые контуры, только https
```

Пока контур один, переменные можно не задавать.

## Как открыть новый контур

1. Регион по требованию закона: код в `DATA_REGIONS`, страны в `REGION_COUNTRIES`, подпись в `DATA_REGION_LABELS`.
   Тот же список стран — в SQL, который заполняет `home_region`. Тест сверяет списки.
2. Поднять установку с `DATA_REGION=<код>`: сервер и база в нужной стране. Каталог площадок — копией справочника.
3. Остальным контурам добавить её адрес в `DATA_REGION_URLS`. С этого момента новые ученики региона регистрируются
   только там.
4. Перенести учеников, которые уже живут не в своём контуре. Их список:
   ```sql
   SELECT id, email, country FROM users WHERE home_region = '<код>' AND data_region <> '<код>';
   ```
   (`needsMigration` в `shared/dataRegions.ts`). Перенос — выгрузка данных ученика, загрузка в новый контур с
   `data_region = '<код>'`, удаление в старом. Ученику — письмо со ссылкой на новый адрес. Инструмент переноса
   делаем, когда откроется второй контур.
5. Юридически: уведомление регулятору страны, правки в политике и согласии.

## Вход и площадки

- Ученик входит на сайте своего контура. На чужом контуре его учётной записи нет: вход ответит «не найден».
  Подсказку «выберите страну — откроется ваш сайт» добавим на главную вместе со вторым контуром.
- Партнёрский API площадок (#19) работает на каждом контуре по своему адресу. Площадка отправляет данные ученика
  в его контур: адрес контура приходит при привязке ученика. Персональные данные между контурами не ходят.
