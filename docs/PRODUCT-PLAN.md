# My EPA — цели и план по этапам

Документ от 24.10.2026, уточнён по ответу владельца. Основан на README, CLAUDE.md, `docs/*`, `shared/schema.ts`,
`server/routes/*`, `server/services/*`, `client/src/*`, текстах лендинга и истории коммитов (клон неполный: с апреля 2026).

**Главная цель (слова владельца):** собирать дедлайны, вебинары и программы обучения ученика и помогать ему
распределять внимание и время.

**Модель проекта (уточнение владельца):** My EPA собирает весь спектр онлайн-обучения ученика, включая
международные площадки. С каждой площадкой заключается договор и налаживается обмен данными: через API площадки
или через наш формат выгрузки (партнёрский API My EPA). Ученик получает дашборд и календарь с напоминаниями и
ссылками на материалы, уроки и экзамены. Значит, **обмен данными с площадками — ядро продукта**, а ручной ввод и
разбор писем — запасные пути для площадок без договора.

Задачи: план — #16; этапы — #17, #19, #18, #20, #21, #22 (в порядке этапов 1–6).

## 1. Зачем My EPA и для кого

**Основной пользователь** — ученик, который учится сразу на нескольких онлайн-площадках, российских и
международных (Stepik, Coursera, edX, Udemy, Skillbox, курс вуза и т. п.). Типичная неделя:

- 2–3 живых вебинара или урока в разное время (часто в разных часовых поясах), ссылки приходят письмом за час;
- 3–6 сроков сдачи и экзаменов (домашки, тесты, мягкие и жёсткие дедлайны), у каждой площадки — свой кабинет;
- материалы к урокам разбросаны по площадкам;
- 5–8 свободных часов на учёбу, которые съедает то, что «горит», а не то, что важно.

Боль: всё разбросано по площадкам, письмам и чатам; вебинары пропускаются; про дедлайн вспоминают в последний день;
нет понимания, хватит ли времени на неделю.

**Обещание My EPA:** открыл один экран — видишь все уроки, вебинары, дедлайны и экзамены со всех площадок в
одном календаре, со ссылками прямо на урок и материал; вовремя получаешь напоминание; знаешь, что делать сегодня;
вебинар, на который не попадаешь, записывается сам.

**Ценность для площадки-партнёра:** ученики меньше бросают курс (напоминания, план), площадка видна в каталоге
My EPA, интеграция — один раз по общему формату, а не под каждого агрегатора.

## 3. Цели продукта

| # | Цель | Как мерим |
|---|---|---|
| Ц1 | Всё обучение ученика в одном календаре: уроки, вебинары, дедлайны, экзамены, ссылки на материалы | ≥ 90 % событий недели приходят от площадок автоматически (доля событий из обмена против ручных) |
| Ц2 | Обмен данными с площадками | число площадок с работающим обменом: 3 к концу этапа 2, 10 через полгода; свежесть данных ≤ 1 ч для партнёрского API |
| Ц3 | Ни один вебинар, урок или экзамен не пропущен | 100 % событий имеют напоминание; для отмеченных «не смогу» — запись в Help Recorder создана заранее |
| Ц4 | Ни один дедлайн не просрочен «по забывчивости» | доля просроченных < 5 %; напоминание пришло ≥ 24 ч до срока |
| Ц5 | Есть план на неделю с учётом доступного времени | у активного ученика каждую неделю есть план; нагрузка ≤ заявленного времени или явное предупреждение |
| Ц6 | Ученик возвращается | WAU/MAU ≥ 40 %; экран «Сегодня» открывают ≥ 3 раз в неделю |

## 4. Пути решения

### 4.1. Как получать данные с площадок

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. Адаптеры к API площадок (Stepik, Coursera, edX, Moodle REST, Canvas…) | данные точные, с прогрессом; площадке ничего не надо делать | API у каждой свой, часто без расписания вебинаров и материалов; на каждую — отдельная работа и поддержка; у многих API закрыт или только для B2B |
| B. Партнёрский API My EPA: наш открытый формат, площадка по договору присылает данные сама (push) или публикует выгрузку, которую мы забираем (pull) | один формат на все площадки; в формате есть всё, что нужно ученику (уроки, материалы, экзамены, вебинары); масштабируется договорами, а не нашим кодом | площадке нужно сделать интеграцию; без договора не работает; нужны песочница, документация, поддержка партнёров |
| C. Стандарты EdTech: iCalendar (расписание), 1EdTech LTI 1.3 / OneRoster / Caliper, xAPI | у части площадок уже есть, особенно у вузовских LMS | покрывают разные куски; сложные; коммерческие площадки их редко отдают наружу |
| D. Запасные пути без договора: ручной ввод одной строкой, подписка на iCal, пересылка писем-уведомлений на личный адрес, расширение браузера | работают с любой площадкой | менее точны, нужна дисциплина ученика или подтверждение |
| E. Робот входит в кабинет по логину/паролю ученика | полностью автоматически | хрупко, юридически и по безопасности рискованно; сейчас пароли уже хранятся впустую |

**Рекомендация:** B как основной путь, A — для крупных площадок, у которых свой API уже есть и которые не будут
делать интеграцию под нас, C — как «входы» в тот же формат (iCal и xAPI принимаем сразу), D — запасной путь для
площадок без договора. Внутри — одна модель событий и одна схема «источник → адаптер → нормализация → лента»: любой
путь (A, B, C, D) — это адаптер в одну и ту же модель. E не делать; сохранённые пароли удалить (вопрос 4).

### 4.2. Каким сделать партнёрский API

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. Push: площадка шлёт изменения на наш API (`POST /partner/v1/...`) с ключом партнёра | данные свежие; нам не нужно ходить по площадкам | площадке нужно писать отправку и повторы |
| B. Pull: площадка публикует выгрузку (JSON-фид по ученику или пакет на всех), мы забираем по расписанию | площадке проще всего (как RSS); легко отлаживать | задержка до интервала опроса; нагрузка на опрос |
| C. Оба, с одной схемой данных | площадка выбирает, что ей проще | два пути в поддержке |

**Рекомендация:** C, начать с B (быстрее договориться с площадкой), A — для тех, кто готов. Основные решения:
- **сущности формата:** программа/курс → модуль → урок или событие (`lesson`, `webinar`, `assignment`, `exam`,
  `deadline`) с началом, длительностью, часовым поясом, ссылкой на урок, материалами (ссылки), признаком
  обязательности; прогресс ученика; внешние id для дедупликации;
- **привязка ученика:** ученик в My EPA нажимает «подключить площадку» → OAuth или одноразовый код у площадки →
  площадка получает наш id ученика и согласие на передачу данных; для pull — личная ссылка-фид ученика;
- **документы:** OpenAPI + JSON Schema, валидатор, песочница, тестовый ключ, страница статуса обмена для партнёра;
- **версии:** `/partner/v1`, обратная совместимость, журнал изменений.

Опыт уже есть: My EPA сам ходит в партнёрский API Help Recorder (ключ партнёра, `Idempotency-Key`, вебхук с
HMAC-подписью, `docs/HELP-RECORDER.md`) — тот же подход можно отзеркалить для площадок.

### 4.3. Как распределять внимание и время

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. Дашборд и календарь «Сегодня / Неделя» + напоминания (email, Telegram, push) | просто, сразу полезно | не говорит, *когда* учиться |
| B. Недельный план: ученик задаёт свободные слоты и часы, у задач — оценка длительности и приоритет; планировщик раскладывает по слотам, показывает перегруз | прямо отвечает на «распределять время»; предсказуемо | первые недели оценки неточны |
| C. ИИ-помощник строит и перестраивает план, объясняет выбор | гибко | непредсказуемо, дорого, без данных из A/B бесполезно |

**Рекомендация:** A → B → C поверх B. Длительность уроков и оценки нагрузки по возможности берём из данных
площадки (поле в формате обмена), а не просим ученика.

### 4.4. Как связать вебинары с записью через Help Recorder

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. Кнопка «Записать» в карточке вебинара: создаёт задачу через существующий `POST /api/recording/schedule` с заполненными ссылкой, временем, длительностью | минимум работы, код записи не трогаем; ученик сам подтверждает право на запись | нужно нажать |
| B. Правило «записывать все вебинары курса X» | ни один не пропущен автоматически | расход лимитов; согласие на запись нужно заранее; с партнёром — оговорить в договоре |
| C. Площадка-партнёр сама отдаёт запись вебинара в формате обмена (ссылка) | записывать не нужно, официально | только у тех, кто записывает сам |

**Рекомендация:** C, где площадка отдаёт запись; иначе A, позже B как опция. Связь хранится у события
(`recording_task_id`), код `server/services/helpRecorder` и `server/services/recording` не меняется. Запись
кладётся в библиотеку курса.

## 5. Этапы

Порядок учитывает, что переговоры с площадками идут долго: спецификацию формата (этап 2) стоит опубликовать как
можно раньше, параллельно с этапом 1, чтобы показывать её площадкам.

### Этап 1. Единая модель и календарь ученика (#17)
- **Цель:** одно место для всего обучения; модель данных, которая станет основой формата обмена.
- **Ученик получает:** дашборд «Сегодня» и календарь «Неделя / Месяц» с уроками, вебинарами, дедлайнами и
  экзаменами всех курсов; у события — ссылки «Открыть урок», «Материалы», «Войти на вебинар», «Записать»
  (Help Recorder); быстрый ручной ввод одной строкой.
- **Работы:** модель «программа → модуль → событие» (`lesson`, `webinar`, `assignment`, `exam`, `deadline`;
  начало, длительность, часовой пояс, ссылки на урок и материалы, источник, внешний id); слить `deadlines` +
  `course_deadlines` и `courses` + `external_courses` с миграцией данных; дашборд и календарь; учёт часовых поясов
  и языка; кнопка «Записать» → `/api/recording/schedule`; ИИ-контекст — на новую модель; убрать случайные данные
  из аналитики.
- **Готово, когда:** события Stepik и ручные видны в одном календаре в часовом поясе ученика; у каждого — рабочая
  ссылка на урок или материал; запись из карточки вебинара доходит до «Готово».
- **Зависимости:** вопросы 1, 7.

### Этап 2. Обмен данными с площадками: формат My EPA, партнёрский API, адаптеры (#19)
- **Цель:** данные приходят от площадок автоматически (Ц1, Ц2).
- **Ученик получает:** кнопку «Подключить площадку» для партнёров; программы, расписание, материалы и экзамены
  появляются сами и обновляются; статус каждого подключения.
- **Площадка получает:** документацию, песочницу, тестовый ключ, валидатор выгрузки, страницу статуса обмена.
- **Работы:** спецификация формата (OpenAPI + JSON Schema) и публичная страница для партнёров; партнёрский API v1:
  pull-фид и push-эндпоинты, ключи партнёров, идемпотентность, вебхуки с подписью; привязка ученика (OAuth /
  одноразовый код / личная ссылка) с согласием на передачу данных; каркас адаптеров «источник → нормализация →
  лента», фоновая синхронизация по расписанию, журнал ошибок; адаптеры: Stepik (починить OAuth — один
  `redirect_uri`), iCal-импорт, первая площадка-партнёр; учёт партнёров в админке (договор, ключи, статус).
- **Готово, когда:** первая площадка-партнёр передаёт данные через v1 в проде; Stepik синхронизируется сам;
  изменение урока на площадке видно ученику ≤ 1 ч (pull) или ≤ 1 мин (push).
- **Зависимости:** этап 1 (модель); вопросы 2, 11–14; договор с первой площадкой.

### Этап 3. Напоминания и календарь наружу (#18)
- **Цель:** ни одно событие не забыто (Ц3, Ц4).
- **Ученик получает:** напоминание за N часов до дедлайна и экзамена, за 15 мин до урока или вебинара — со
  ссылкой на урок и материалы; утреннюю сводку и недельный дайджест; iCal-ссылку на свою ленту для Google /
  Яндекс / Apple / Outlook календаря.
- **Работы:** планировщик напоминаний на готовых полях (`reminderAdvance`, `deadlineReminders`, `weeklyDigest`);
  каналы: email (SMTP уже есть), Telegram, web-push; учёт часового пояса ученика; экспорт `.ics` по секретной
  ссылке; опция «записывать все вебинары курса».
- **Готово, когда:** напоминания уходят по расписанию без дублей и в правильном часовом поясе (тесты); ics
  открывается в Google и Яндекс Календаре и обновляется.
- **Зависимости:** этап 1; вопрос 3.

### Этап 4. План недели с учётом времени (#20)
- **Цель:** ученик знает, когда что делать, и видит перегруз заранее (Ц5).
- **Ученик получает:** настройку «сколько часов и в какие дни»; авто-раскладку уроков и заданий по слотам до
  дедлайнов (длительность — от площадки или оценкой); предупреждение о перегрузе с предложением, что перенести;
  таймер учёбы и факт против плана.
- **Работы:** слоты доступности; оценка длительности и приоритет у событий; детерминированный планировщик;
  экран плана с переносом; `study_sessions` и честная аналитика.
- **Готово, когда:** план для 50 событий строится < 1 с, не ставит задачу после её дедлайна и не превышает
  заявленное время без предупреждения (тесты).
- **Зависимости:** этапы 1, 3; длительности из этапа 2 желательны.

### Этап 5. ИИ-помощник поверх данных (#21)
- **Цель:** помощник, который знает всё расписание и экономит время.
- **Ученик получает:** «перестрой неделю, я болею до среды», оценки длительности, недельный разбор, конспект по
  записи вебинара (если Help Recorder отдаёт расшифровку).
- **Работы:** история чата в БД; инструменты ИИ: читать ленту, предлагать изменения плана — только с
  подтверждением; ИИ-разбор писем и страниц (общий с этапом 6); лимиты по тарифу.
- **Готово, когда:** изменения от ИИ всегда идут через подтверждение; ответы ссылаются на реальные события.
- **Зависимости:** этап 4; вопросы 8, 9.

### Этап 6 (дальний). Площадки без договора и мобильный доступ (#22)
- **Цель:** закрыть площадки, с которыми договора ещё нет; быть под рукой.
- **Работы:** пересылка писем-уведомлений на личный адрес ученика и разбор (шаблоны + ИИ) с экраном
  подтверждения; расширение браузера, которое считывает расписание из открытого кабинета площадки; PWA с
  push-уведомлениями. Статистика ручного ввода подсказывает, с какими площадками договариваться следующими.
  Нативное мобильное приложение My EPA пока не планируется (решение владельца: сейчас приложения делаются
  только для Help Recorder).
- **Зависимости:** этапы 1–3.

## 6. Вопросы владельцу

1. **Кто основной ученик:** взрослый на онлайн-курсах, студент, школьник? От этого зависят интерфейс и каналы
   напоминаний.
2. **С какими площадками договор ближе всего** (первые 3)? С кем уже идут переговоры, у кого есть свой API?
3. **Каналы напоминаний:** email, Telegram, web-push — что первым?
4. **Логины/пароли площадок** сейчас шифруются и хранятся, но не используются. Удалить функцию и данные
   (рекомендую)?
5. **Лендинг** обещает Coursera, edX и «умный календарь». Оставить как цель или пометить «скоро»?
6. **Аналитика** рисует график на случайных числах. Скрыть до этапа 4?
7. **Данные на проде:** есть ли пользователи с синхронизированными курсами Stepik и с ручными курсами/дедлайнами?
   Работает ли сейчас вход через Stepik, какой `redirect_uri` зарегистрирован? Нужно для миграции.
8. **Тарифы:** что платное для ученика? Платят ли площадки (или наоборот, мы им — за данные)? Лимиты тарифов сейчас
   заданы, но не проверяются.
9. **Записи:** README говорит про воркер Night Recorder, `docs/HELP-RECORDER.md` — про Help Recorder. Что актуально
   на проде? Будет ли расшифровка речи?
10. **Автозапись вебинаров** по правилу на курс допустима, или только по кнопке? Как это оговаривать с площадками?
11. **Формат обмена:** делаем свой открытый (рекомендую, с приёмом iCal и xAPI) или берём за основу стандарт
    (LTI / OneRoster / Caliper)? Будет ли спецификация публичной?
12. **Привязка ученика к площадке:** через OAuth площадки, одноразовый код или по email? Кто хранит согласие ученика
    на передачу данных?
13. **Право и данные:** площадки международные — где хранятся персональные данные (152-ФЗ требует хранить данные
    граждан РФ в РФ; для ЕС — GDPR)? Нужен ли типовой договор об обмене данными и DPA?
14. **Кто ведёт партнёров:** нужен ли кабинет партнёра (ключи, статус обмена, статистика) сразу или достаточно
    выдачи ключей через админку на первых площадках?
